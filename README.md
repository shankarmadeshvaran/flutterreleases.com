# flutterreleases.com

Browse every Flutter release — version, Dart SDK, channel, downloads, and release notes — in one place. Updated daily via GitHub Actions.

**Live site:** [flutterreleases.com](https://flutterreleases.com)

---

## Stack

| Layer | Tech |
|---|---|
| Frontend | React 19 + Vite 7 + Tailwind CSS v4 |
| Routing | Wouter |
| Build | Bun + Turborepo monorepo |
| Deploy | Cloudflare Pages (via GitHub Actions) |
| Data pipeline | Node.js scripts + GitHub Actions (daily cron) |

## Project Structure

```
.github/
  workflows/
    deploy.yml                  ← Builds + deploys to Cloudflare Pages on push to main
    crawl-releases.yml          ← Daily cron: crawls Flutter releases API → releases.json
    update-releases.yml         ← Regenerates feed.xml when releases.json changes
    validate-release-data.yml   ← Guardrail: fails on schema drift or suspiciously small data

  crawl-releases.js             ← Hits Flutter SDK archive + GitHub API, writes releases.json
  generate-release-pages.js     ← Post-build: generates per-release HTML, sitemap.xml,
                                   /flutter-versions/, llms-full.txt, and links.html
                                   from releases.json
  validate-flutter-versions-page.js ← Verifies generated SEO page, latest channels,
                                      release links, and sitemap inclusion

packages/
  web/
    index.html                  ← Entry HTML with meta tags, OG, JSON-LD, canonical,
                                   noscript fallback with top-10 stable links
    vite.config.ts
    vite/
      plugins/
        runable-analytics-plugin.ts  ← Injects analytics script tag at build time
    src/web/
      main.tsx
      app.tsx
      pages/
        index.tsx               ← Main page (filter, search, pagination, dark mode)
        flutter-versions.tsx    ← SPA version history and Flutter ↔ Dart matrix route
      components/
        Hero.tsx                ← Latest stable/beta pills → release notes
        Header.tsx              ← Nav, dark mode toggle
        FilterBar.tsx           ← Channel filter + search
        ReleaseTable.tsx        ← Expandable rows, downloads, release note links
        Pagination.tsx
        Footer.tsx
        ChannelBadge.tsx
      hooks/
        useReleases.ts          ← Fetches + normalises releases.json
        useDarkMode.ts
        useMeta.ts
        use-desktop.ts
      lib/
        api.ts
        utils.ts
      types/
        release.ts              ← Release, Channel, ReleaseType types
    public/
      releases.json             ← Source of truth — written by crawler, never edit manually
      feed.xml                  ← RSS feed — generated by crawl-releases.js
      sitemap.xml               ← Sitemap — generated by generate-release-pages.js (~393 URLs)
      links.html                ← Crawlable full release index — generated by generate-release-pages.js
      llms.txt                  ← LLM-friendly schema reference (static, manually maintained)
      llms-full.txt             ← LLM-friendly full stable release table — auto-generated
      robots.txt
      og-image.png
      site.webmanifest
      feed.xsl                  ← Styles the RSS feed in browsers
```

> `dist/` mirrors `public/` after build. `generate-release-pages.js` writes to both.

## Local Development

```sh
git clone https://github.com/shankarmadeshvaran/flutterreleases.com.git
cd flutterreleases.com
bun install
bun run dev        # Vite dev server at http://localhost:5173
```

Copy `.env.template` to `.env` and set `GITHUB_TOKEN` if you want to run the crawler locally (avoids GitHub API rate limits).

## Build

```sh
bun run build:web                        # Vite build → packages/web/dist
node scripts/generate-release-pages.js   # Post-build: generate per-release pages + sitemap
```

## Data Pipeline

| Step | Trigger | What it does |
|---|---|---|
| `crawl-releases.yml` | Daily 06:00 UTC + manual | Hits Flutter SDK archive + GitHub metadata, writes canonical `releases.json`, commits |
| `update-releases.yml` | Push to `releases.json` or `scripts/` | Regenerates `feed.xml`, commits |
| `validate-release-data.yml` | Push to release data / schema files | Fails CI if schema drifts or item count drops below threshold |
| `deploy.yml` | Push to `main` | Builds Vite app, runs `generate-release-pages.js`, deploys to Cloudflare Pages |

### Running the crawler locally

```sh
node scripts/crawl-releases.js                 # stable channel only
node scripts/crawl-releases.js --all-channels  # stable + beta + dev + main
```

### Regenerating all static assets locally

```sh
# Run after bun run build:web — reads from dist/, falls back to public/
SITE_URL=https://flutterreleases.com node scripts/generate-release-pages.js

# Options
node scripts/generate-release-pages.js --dry-run      # Preview counts, no writes
node scripts/generate-release-pages.js --stable-only  # Only generate stable release pages
```

This produces:
- `dist/release/<version>/index.html` — one page per release (~387 pages)
- `dist/flutter-versions/index.html` — crawlable Flutter version history and Dart compatibility page
- `dist/sitemap.xml` + `public/sitemap.xml` — all top-level and per-release URLs
- `dist/llms-full.txt` + `public/llms-full.txt` — full stable release table for LLMs
- `dist/links.html` + `public/links.html` — crawlable full release index (no JS)

## SEO & Discoverability

Every file generated by `generate-release-pages.js` serves a specific discovery channel:

| File | Purpose | Audience |
|---|---|---|
| `sitemap.xml` | Tells search engines about every URL | Googlebot, Bingbot |
| `feed.xml` | RSS feed of stable + beta releases | RSS readers, aggregators |
| `releases.json` | Machine-readable full release dataset | Developers, scripts |
| `llms.txt` | Schema reference (field names, types, conventions) | LLM crawlers (GPTBot, Claude) |
| `llms-full.txt` | Full stable release table in Markdown | LLM context windows |
| `links.html` | Crawlable page listing all 387 release links | Crawlers without JS |
| `/flutter-versions/` | Static Flutter version history, latest stable/beta/dev, and Flutter ↔ Dart compatibility | Search engines, LLMs, developers |
| `/release/<version>` | Individual release page with JSON-LD + downloads | Search engines, LLMs |

**Flutter versions page** (`/flutter-versions/`) is generated from `releases.json` on every post-build run. It serves full static HTML with the latest stable, beta, and dev/main releases, grouped version history, Dart SDK compatibility rows, JSON-LD, canonical metadata, and links to every individual release page.

**Per-release pages** (`/release/3.44.1`, etc.) redirect JS-enabled users to the SPA (`/?v=3.44.1#release`) but serve full static HTML to crawlers — so each release is independently indexable.

The homepage links to `/flutter-versions/` through normal anchor links in the nav/hero/footer and the `<noscript>` fallback. Release pages also link back to `/flutter-versions/`, creating crawlable paths between the SEO hub and individual release pages.

## Deploy

Push to `main` → `deploy.yml` builds, runs the generator, and deploys automatically.

### Required GitHub Secrets

| Secret | Where to get it |
|---|---|
| `CLOUDFLARE_API_TOKEN` | Cloudflare → My Profile → API Tokens → Create Token (Pages:Edit) |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare → Workers & Pages overview → right sidebar |
| `SITE_URL` | Set to `https://flutterreleases.com` (used by generator for sitemap URLs) |

### Cloudflare Pages project (one-time setup)

```sh
bunx wrangler pages project create flutterreleases
```

Or create it in the Cloudflare dashboard under **Workers & Pages → Create application → Pages**.

## Release Data Contract

`releases.json` is the single source of truth. Every item must include:

| Field | Example |
|---|---|
| `version` | `"3.44.0"` |
| `channel` | `"stable"` \| `"beta"` \| `"dev"` \| `"main"` |
| `released` | `"2025-05-20"` |
| `dart_version` | `"3.7.0"` |
| `requires` | `{ "xcode": "...", "android_sdk": "..." }` |
| `platforms` | Object of download URLs keyed by platform |
| `release_notes` | Object with at minimum a `base` URL |

Never edit `releases.json` manually — the crawler owns it.

## Contributing

1. Fork the repo
2. Create a branch: `git checkout -b feat/your-feature`
3. Make changes, run `bun run build:web` to verify
4. Open a PR against `main`

PRs are reviewed before merging. Only merged PRs trigger a deploy.

### Rules

**Do:**
- Keep `releases.json` in the crawler schema — update `useReleases.ts` if you change the shape
- Run `bun run build:web && node scripts/generate-release-pages.js` locally before opening a PR
- Run `node scripts/validate-flutter-versions-page.js` after generating static pages when touching SEO output
- Use `SITE_URL` env var in scripts for base URLs

**Don't:**
- Don't edit `releases.json`, `feed.xml`, `sitemap.xml`, `llms-full.txt`, `/flutter-versions/`, or `links.html` manually — they're auto-generated
- Don't use `npm` — this repo uses Bun workspaces
- Don't remove or weaken the `validate-release-data.yml` guardrail
- Don't reintroduce `flutter_version`-only release objects (legacy schema — normalised in the generator)
