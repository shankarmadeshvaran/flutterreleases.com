# flutterreleases.com

Browse every Flutter release — version, Dart SDK, channel, downloads, and release notes — in one place. Updated daily via GitHub Actions.

**Live site:** [flutterreleases.com](https://flutterreleases.com)

---

## Stack

| Layer | Tech |
|---|---|
| Frontend | React 19 + Vite 7 + Tailwind CSS v4 |
| Routing | Wouter |
| Build | Bun + Turborepo monorepo |
| Deploy | Cloudflare Pages (via GitHub Actions) |
| Data pipeline | Node.js scripts + GitHub Actions (daily cron) |

---

## Project Structure

```
.github/
  workflows/
    deploy.yml                  ← Builds + deploys to Cloudflare Pages on push to main
    crawl-releases.yml          ← Daily cron: crawls Flutter releases API → releases.json
    update-releases.yml         ← Regenerates feed.xml + sitemap.xml when data changes
    validate-release-data.yml   ← Guardrail: fails on schema drift or suspiciously small data

scripts/
  crawl-releases.js             ← Hits Flutter SDK archive + GitHub API, writes releases.json
  generate-releases.js          ← Generates feed.xml, sitemap.xml, generation_status.json

packages/

    index.html                  ← Entry HTML with meta tags, OG, JSON-LD, canonical
    vite.config.ts
    vite/
      plugins/
        runable-analytics-plugin.ts  ← Injects analytics script tag at build time
    src/web/
      main.tsx
      app.tsx
      pages/
        index.tsx               ← Main page (filter, search, pagination, dark mode)
      components/
        Hero.tsx                ← Latest stable/beta pills → release notes
        Header.tsx              ← Nav, dark mode toggle
        FilterBar.tsx           ← Channel filter + search
        ReleaseTable.tsx        ← Expandable rows, downloads, release note links
        Pagination.tsx
        Footer.tsx
        ChannelBadge.tsx
      hooks/
        useReleases.ts          ← Fetches + normalises releases.json
        useDarkMode.ts
        useMeta.ts
        use-desktop.ts
      lib/
        api.ts
        utils.ts
      types/
        release.ts              ← Release, Channel, ReleaseType types
    public/
      releases.json             ← Source of truth — written by crawler, never edit manually
      feed.xml                  ← RSS feed — generated by generate-releases.js
      sitemap.xml               ← Sitemap — generated by generate-releases.js
      llms.txt                  ← LLM-friendly plain text index
      robots.txt
      og-image.png
      site.webmanifest
      feed.xsl                  ← Styles the RSS feed in browsers
```

## Local Development

```sh
git clone https://github.com/shankarmadeshvaran/flutterreleases.com.git
cd flutterreleases.com
bun install
bun run dev        # Vite dev server at http://localhost:5173
```

Copy `.env.template` to `.env` and set `GITHUB_TOKEN` if you want to run the crawler locally (avoids GitHub API rate limits).

## Build

```sh
bun run build:web  # outputs to packages/web/dist
```

## Data Pipeline

| Workflow | Trigger | What it does |
|---|---|---|
| `crawl-releases.yml` | Daily 06:00 UTC + manual | Hits Flutter SDK archive + GitHub metadata, writes canonical `releases.json`, commits |
| `update-releases.yml` | Push to `releases.json` or `scripts/` | Regenerates `feed.xml`, `sitemap.xml`, `generation_status.json` |
| `validate-release-data.yml` | Push to release data / schema files | Fails CI if schema drifts or item count drops below threshold |
| `deploy.yml` | Push to `main` | Builds Vite app, deploys to Cloudflare Pages |

### Running the crawler locally

```sh
node scripts/crawl-releases.js                 # stable channel only
node scripts/crawl-releases.js --all-channels  # stable + beta + dev + main
```

### Regenerating feed + sitemap locally

```sh
SITE_URL=https://flutterreleases.com node scripts/generate-releases.js
```

## Deploy

Push to `main` → `deploy.yml` builds and deploys automatically.

### Required GitHub Secrets

| Secret | Where to get it |
|---|---|
| `CLOUDFLARE_API_TOKEN` | Cloudflare → My Profile → API Tokens → Create Token (Pages:Edit) |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare → Workers & Pages overview → right sidebar |
| `SITE_URL` | Set to `https://flutterreleases.com` (used by generator for sitemap URLs) |

### Cloudflare Pages project (one-time setup)

```sh
bunx wrangler pages project create flutterreleases
```

Or create it in the Cloudflare dashboard under **Workers & Pages → Create application → Pages**.

## Release Data Contract

`releases.json` is the single source of truth. Every item must include:

| Field | Example |
|---|---|
| `version` | `"3.44.0"` |
| `channel` | `"stable"` \| `"beta"` \| `"dev"` \| `"main"` |
| `released` | `"2025-05-20"` |
| `dart_version` | `"3.7.0"` |
| `requires` | `{ "xcode": "...", "android_sdk": "..." }` |
| `platforms` | Object of download URLs keyed by platform |
| `release_notes` | Object with at minimum a `base` URL |

Never edit `releases.json` manually — the crawler owns it.

## Contributing

1. Fork the repo
2. Create a branch: `git checkout -b feat/your-feature`
3. Make changes, run `bun run build:web` to verify
4. Open a PR against `main`

PRs are reviewed before merging. Only merged PRs trigger a deploy.

### Rules

**Do:**
- Keep `releases.json` in the crawler schema — update `useReleases.ts` if you change the shape
- Run `bun run build:web` locally before opening a PR
- Use `SITE_URL` env var in scripts for base URLs

**Don't:**
- Don't edit `releases.json`, `feed.xml`, or `sitemap.xml` manually — they're auto-generated
- Don't use `npm` — this repo uses Bun workspaces
- Don't remove or weaken the `validate-release-data.yml` guardrail
- Don't reintroduce `flutter_version`-only release objects (legacy schema)
